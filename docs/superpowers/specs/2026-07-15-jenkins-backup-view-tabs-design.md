# Jenkins 备份汇总按视图分组设计

## 目标

“查看汇总”顶部使用横向标签页展示备份时的 Jenkins 视图。选择视图后，表格只显示该视图包含的 Job。

## 数据结构

新备份把 `details.json` 升级为版本 2，并在现有 `jobs` 外保存视图快照，避免重复存储 Job 详情：

```json
{
  "version": 2,
  "views": [
    {"name": "All", "job_names": ["folder/api", "web"]},
    {"name": "生产环境", "job_names": ["folder/api"]}
  ],
  "jobs": []
}
```

备份服务使用 Jenkins 视图接口获取视图及其 Job，通过 Job URL 与递归备份结果匹配，兼容文件夹内的完整 Job 名称。视图读取失败不应导致备份失败；此时生成一个包含全部已备份 Job 的“全部任务”视图。

## 前端交互

- 汇总标题下方、表格上方显示横向可滚动标签页。
- 默认优先选择名称为 `All` 的视图；没有 `All` 时选择第一个视图。
- 点击标签只过滤当前表格，不重复请求详情接口。
- 同一 Job 属于多个视图时，在相应标签中均可看到。
- 标签显示视图名称和 Job 数量。
- 表格原有横向、纵向滚动及悬停复制行为保持不变。

## 兼容规则

- 版本 1 或缺少 `views` 的历史备份：前端生成“全部任务”标签并显示全部 Job。
- 视图引用了未成功备份的 Job：忽略该 Job。
- 已备份但不属于任何返回视图的 Job：放入“未分类”标签，避免内容丢失。
- `All` 仅作为普通 Jenkins 视图展示，不额外复制一份“全部任务”。

## 验证

- 后端测试覆盖多个视图、同一 Job 属于多个视图、视图接口失败回退。
- 前端测试覆盖默认标签、按视图过滤、历史备份回退和未分类 Job。
- 运行前端生产构建，并只更新 `web` 容器；后端改动完成后更新 `backend` 容器。

## 不做

- 不修改历史 ZIP。
- 不增加搜索、视图排序或用户自定义分组。
- 不新增前端依赖。

# 刷新按钮与外部构建同步修复设计

## 目标

统一所有重新拉取数据按钮的加载反馈，并让 Jenkins 外部手动构建记录与远端实际存在的构建编号保持一致。

## 范围

- 覆盖前端的刷新、刷新列表、查询、同步外部构建、同步任务状态等重新拉取数据操作。
- 加载状态只影响被点击的按钮。
- Jenkins 对账只删除 `release_history.is_external = true` 的外部手动构建记录。
- 系统发布产生的历史记录不因 Jenkins 构建被删除而清理。

## 前端设计

新增一个轻量的共用刷新按钮组件，复用 Naive UI 的 `NButton` 和 `NSpin`，不增加依赖。

组件接收按钮文案、加载状态和禁用状态，并透传 `type`、`size`、`secondary` 等按钮属性。加载时保留文案占用的宽度，但将文案隐藏，在按钮中央覆盖一个 12px 转圈，避免按钮尺寸跳动。转圈颜色使用 `currentColor`：主色按钮上继承白色文字，浅色按钮上继承深色或主题色文字。组件同时设置 `aria-busy` 和稳定的可访问名称。

各页面继续负责自己的请求状态。一个页面存在多个重新拉取按钮时，每个入口使用独立状态；请求结束时只复位本次请求启动的状态，不批量清空其他按钮状态。现有 500ms 最短反馈保留，使快速请求也能被感知。

## 后端设计

在现有 `JenkinsClient` 中增加轻量的构建编号列表查询，只请求 `builds[number]`。成功时返回远端完整编号集合；请求失败时明确返回失败信号，不能把失败解释成“远端没有构建”。

`sync_external_builds` 对每个已配置 Job 执行以下流程：

1. 获取远端完整构建编号集合。
2. 保留现有最近 10 条构建的新增归档流程。
3. 仅在编号集合成功获取后，查找同一服务器名称、同一 Job 名称且 `is_external = true` 的本地记录。
4. 删除其中构建编号不在远端集合内的记录并提交事务。

系统任务对应的 `ReleaseTask` 和 `is_external = false` 历史记录不参与删除。远端查询失败时记录警告并跳过该 Job 的删除对账，避免 Jenkins 临时故障导致数据丢失。

## 数据流

用户点击按钮后，该按钮进入独立加载状态并调用现有接口。外部构建同步接口调用同步服务；同步服务从 Jenkins 获取完整编号集合和最近构建详情，新增缺失的外部记录，再删除远端已不存在的外部记录。接口完成后前端重新拉取列表，最后恢复当前按钮文案。

## 错误处理

- 前端请求失败沿用现有错误提示，且只复位当前按钮状态。
- Jenkins 编号列表请求失败时不删除任何本地记录。
- 单个 Job 的远端数据不可用时不影响已完成 Job 的同步结果。
- 删除条件必须同时限定服务器、Job 和 `is_external = true`。

## 验证

- 不新增自动化回归测试，功能验收由用户人工完成。
- 人工验证加载时文案隐藏、12px 转圈居中、颜色可见，以及同页按钮状态互不影响。
- 人工在 Jenkins 删除一个外部构建编号后执行同步，确认对应外部记录删除，同时系统发布历史和仍存在的外部记录保留。
- 人工模拟或观察 Jenkins 不可用场景，确认同步失败不会删除本地记录。
- 交付前仅运行前端构建与后端 Python 编译检查，排除类型和语法错误。
